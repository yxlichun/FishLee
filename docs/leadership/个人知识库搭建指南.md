# 个人知识库搭建：从工具到思想

> 结合 Andrej Karpathy 在 2026 年提出的 LLM Wiki 模式 + 经典 PARA 方法论 + 工程师视角的完整方案。

---

## 一、思想层（最重要，先想清楚）

### 1. 范式转移：从 RAG 到 LLM Wiki

**这是 2026 年最重要的认知更新**。Andrej Karpathy 提出的 [LLM Wiki](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f) 模式正在颠覆传统 RAG：

| 传统 RAG | LLM Wiki（推荐） |
|---------|-----------------|
| 文档 → embedding → 向量库 → 检索 | 原始资料 → LLM 编译 → 结构化 wiki |
| 黑盒检索，不可解释 | 索引优先，可解释可追溯 |
| 需要维护向量库 | 纯 markdown，零依赖 |
| 适合大规模文档 | 个人级 100~500 篇文章最佳 |

**核心洞察**：在个人知识库这个量级，**LLM 是"编译器"而非"检索器"**。你提供原始资料，LLM 帮你做摘要、打标签、建链接、维护 `_index.md`。

### 2. 核心方法论：CODE × PARA

[Tiago Forte 的 BASB](https://www.buildingasecondbrain.com/) 框架已被 AI 升级：

```
CODE 流程（动作）：
  Capture（捕获）→ Organize（组织）→ Distill（提炼）→ Express（表达）

PARA 结构（分类）：
  Projects（短期项目，有 deadline）
  Areas（长期责任，需维持标准）
  Resources（兴趣资源，未来参考）
  Archives（已完成/不活跃）
```

**关键认知**：[按"可行动性"分类，不按"主题"分类](https://www.buildingasecondbrain.com/para)。例如："AI PM 转型"是 Project，"移动端管理"是 Area，"AI 资讯"是 Resource。

### 3. 三个心法

- **摩擦杀死系统**：捕获超过 10 秒就不会坚持，所以 ArkClaw 自动化非常关键
- **2026 不是缺信息，是缺合成**：每天等于读 174 份报纸的信息量，重点是 Distill
- **输出驱动输入**：没有 Express 的知识库就是数字垃圾场

## 二、工具层（最佳分工）

```
┌──────────────────────────────────────────────────────┐
│  [Express 表达层]                                     │
│  个人网站  ←  飞书文档（精修美化）                      │
└──────────────────────────────────────────────────────┘
                    ↑
┌──────────────────────────────────────────────────────┐
│  [Distill 提炼层] ⭐ 核心                             │
│  Obsidian (GitHub备份) ← Hermes/Qwen 当编译器         │
│  ├── 0_Inbox/      （未处理捕获）                     │
│  ├── 1_Projects/   （PARA-P）                        │
│  ├── 2_Areas/      （PARA-A，工作+生活）              │
│  ├── 3_Resources/  （PARA-R）                        │
│  ├── 4_Archives/   （PARA-X）                        │
│  ├── _index.md     （LLM 入口）                      │
│  └── _vocab.md     （受控标签词表）                   │
└──────────────────────────────────────────────────────┘
                    ↑
┌──────────────────────────────────────────────────────┐
│  [Capture 捕获层]                                     │
│  ArkClaw（资讯）+ 飞书（速记）+ 手机随手记 + 微信收藏    │
└──────────────────────────────────────────────────────┘
```

### 工具职责清单

| 工具 | 角色 | 核心职责 |
|-----|------|---------|
| **ArkClaw** | 自动化采集 | AI/财经资讯日报 → 飞书 Inbox |
| **飞书文档** | 协作 + 精修 | 团队共享、需要美观排版的最终稿 |
| **Obsidian** | 个人大脑 | 所有知识的"唯一可信源"（Single Source of Truth） |
| **GitHub** | 版本备份 + 公开 | obsidian-git 自动同步，部分仓库公开做 Digital Garden |
| **Hermes/Qwen** | LLM 编译器 | 摘要、打标签、维护 `_index.md`、做 Q&A |
| **个人网站** | Express 出口 | 学习路径展示 + 精选文章发布 |

## 三、流程层（具体怎么跑起来）

### 1. 每日流程（10 分钟）

```
早晨：
  ArkClaw → 飞书 → 扫一眼，有价值的 ⭐ 标记
  Qwen 自动把 ⭐ 内容生成 md → Obsidian/0_Inbox

随时：
  灵感/想法 → 飞书速记 / Obsidian 手机端 → 0_Inbox

晚上（5 分钟）：
  清空 0_Inbox：
    - 删（无价值）
    - 归档（PARA 分类，丢到 1/2/3）
    - 升级（值得展开 → 新建笔记 + [[双向链接]]）
```

### 2. 每周流程（30 分钟）⭐ 关键

```
周日晚上：
  1. 跑 Qwen 脚本：扫描本周新增笔记，更新 _index.md
  2. 审视 1_Projects/：哪些进展？哪些卡住？
  3. 让 Qwen 找"孤岛笔记"（无任何链接的）→ 强制建链或归档
  4. 选 1-2 篇 Resource 升级为博客文章 → 发个人网站
```

### 3. 每月流程（1 小时）

```
月末：
  - PARA 大扫除：完成的 Project → Archives
  - 让 Qwen 生成"本月知识图谱报告"（新增了哪些主题、链接密度变化）
  - 检查覆盖度：哪些 Area 一个月没更新？是否需要补充？
```

### 4. 知识健康度的 5 个指标

| 指标 | 健康值 | 怎么测 |
|-----|--------|--------|
| 链接密度 | 平均每篇 ≥ 3 个链接 | Obsidian Graph View |
| 孤岛率 | < 10% | dataview 插件查 |
| Inbox 滞留 | < 7 天 | 文件创建时间 |
| Project 完成率 | 季度 ≥ 70% | 手动统计 |
| Express 输出 | 月 ≥ 2 篇 | 网站发布数 |

## 四、覆盖度：怎么保证全面（生活+工作）

用 **PARA 矩阵** 自检，每个格子都要有内容：

| | 工作 | 生活 |
|---|------|------|
| **Projects** | AI PM 转型、研效项目、晋升答辩 | 装修、旅行规划、健身计划 |
| **Areas** | 移动端管理、技术委员会、团队培养 | 健康、家庭、财务、人脉 |
| **Resources** | AI 论文、PM 方法论、行业报告 | 菜谱、读书笔记、影视收藏 |

**强制覆盖技巧**：在 Obsidian 建一个 `_dashboard.md`，用 dataview 查询每个 Area 最近一次更新时间。超过 30 天没更新的高亮红色 → 提醒补充。

## 五、运用层：怎么榨干价值（重点！）

### 1. 服务大模型的 5 种玩法

#### 玩法 ① LLM Wiki Q&A
```
你问：「我之前对 AI Agent 编排有什么观点？」
Qwen 读 _index.md → 定位到 3 篇笔记 → 综合回答 + 引用源文件
```
**关键**：让 LLM "像人类专家一样导航"，先读目录，再读详情，可解释可追溯。

#### 玩法 ② 写作辅助 / 第二大脑
```
你写晋升 PPT 时，Qwen 自动召回：
  - 你过去 1 年所有项目笔记
  - 你写过的相关思考
  - 你保存的行业数据
→ 生成初稿，你只需精修
```

#### 玩法 ③ 决策辅助
```
"我应该接 X 项目吗？"
Qwen 综合：你的 Areas 优先级 + 当前 Projects 负载 + 历史决策模式 
→ 给出建议
```

#### 玩法 ④ 自动化资讯整理（升级版）
```
ArkClaw 抓资讯 → Qwen 对照你的 Areas/Resources →
  - 自动打标签
  - 自动关联已有笔记 [[xxx]]
  - 重要的推送到飞书提醒你
```

#### 玩法 ⑤ 个人 Agent
```
基于你的知识库训练 Agent：
  - "AI PM 转型教练"：根据你的进度推荐下一步
  - "晋升答辩助手"：从知识库提取项目亮点
  - "技术委员会助理"：回答跨团队技术问题
```

### 2. 让 LLM 用得爽的 5 个写作规范

借鉴 [Karpathy 的实践](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)：

```markdown
---
title: AI Agent 编排的 3 种模式
summary: 对比 Workflow/Reactive/Planning 三种编排模式的适用场景  ← 必填
tags: [AI-Agent, 架构, Project::AI-PM转型]  ← 受控词表
status: draft | refined | archived
created: 2026-04-21
---

# 标题

(正文用 [[双向链接]] 关联其他笔记)
```

**5 条铁律**：
1. **每篇必有 summary**：LLM 读索引时只看这一句
2. **小文件优先**：1000 字一篇 > 10000 字一篇
3. **受控标签**：维护 `_vocab.md`，禁止随意打新标签
4. **标注来源**：`#extracted`（原文）/ `#inferred`（推理）/ `#ambiguous`（存疑）
5. **强制双向链接**：每篇至少链接 3 篇相关笔记

## 六、30 天启动计划

| 周 | 任务 |
|----|------|
| **W1** | 在 Obsidian 建 PARA 4 个文件夹 + `_index.md` + `_vocab.md`；GitHub 备份 |
| **W2** | 把现有飞书文档按 PARA 分类导入 Obsidian；建立第一批双向链接 |
| **W3** | 在 Hermes 上写 Qwen 脚本：自动维护 `_index.md` + 摘要打标签 |
| **W4** | 跑通完整流程：ArkClaw → Inbox → Distill → 发一篇文章到个人网站 |

## 七、避坑提醒（工程师最容易犯的）

1. **不要过度工程化**：先跑流程，再优化工具。别一上来花两周写自动化脚本。
2. **不要追求"完美分类"**：PARA 模糊地带很多，丢错了也能搜到。
3. **不要建"只进不出"的仓库**：没有 Express 环节，知识库就是垃圾场。
4. **不要全自动化**：Distill 必须手动思考，这是知识内化的关键。
5. **不要多个 SSOT**：飞书 ↔ Obsidian 必须有一个是"主"，建议 Obsidian 为主。

---

## 一句话核心

> **建知识库的目的不是"存"，是"用 LLM 把你的过去 × 现在 × 未来连接起来"。**
>
> Obsidian 是你的硬盘，Qwen 是你的 CPU，PARA 是你的文件系统，CODE 是你的工作流。
